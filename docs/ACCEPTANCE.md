## 浏览器实测

Chromium，桌面 1440×960、手机 390×844、窄屏 320×720。

- 搜索“嘉年华”，选择目的地，出现实际 7.9 km / 7.1 km 路线方案。
- 开始导航后出现绿色路线，指引距离随车辆位置更新。
- “偏离原路线”后自动完成新路线请求，保留目的地并继续行驶。
- “驶出道路”后显示距最近道路约 510 m 的琥珀色虚线与返回指引；点击模拟返回后逐步靠近，回到道路后重新算路并恢复驾驶。
- 东京塔短途导航到达、重新导航、暂停操作通过。
- 收藏目的地后按钮变为“取消收藏目的地”，刷新后数据仍保留。
- 最新布局中不存在品牌页头，导航定位为蓝色箭头，右侧工具栏位于黑色导航栏下方。
- 手机 document.scrollWidth 与 viewport 同为 390，无页面横向溢出。

- 320 像素窄屏下，长地名“立山黑部阿尔卑斯山脉路线”未溢出，页面宽度与视口一致。
- 注入算路接口 503 后显示失败反馈，恢复服务并点击重新计算后成功获得路线。
- 生产版本浏览器无非预期运行错误（仅有测试主动注入的 503）。

## Go 重构与独立运行包

- 9 项 Go 测试通过，`go test -race ./...` 与 `go vet ./...` 通过；另有 2 项前端路线进度投影测试通过。
- 对全部 74 个地标，将 Node 与 Go 返回的方案、距离、时间、点数、指引数逐一比较，一致。
- 路网从独立 data 目录加载，损坏 CSR、未知路段引用（合法 -1 连接弧除外）及缺失数据文件会被拒绝。
- UDP 两目标逐字节转发验证通过；无效布局仍转发，但不更新车辆；关闭转发、回指自身、断流状态通过测试。
- 浏览器使用合成 UDP 包驱动：90→108 km/h、约 500 m 路线进度、远离道路 465 m 的返回指引、回到道路后的自动重新算路均通过。
- 停止发包后网页显示断流与 0 km/h，继续发包后恢复 60 km/h；未回退到 mock。
- 已构建 Windows amd64、macOS arm64、Linux amd64 包。macOS arm64 包在源码目录之外启动成功，默认读取二进制旁配置，HTTP / UDP 正常监听。Windows/Linux 为交叉编译验证，未在对应操作系统实际运行。
